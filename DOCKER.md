# Запуск SIGame веб-стола в Docker

Сайт работает как **один Node-процесс**: Express раздаёт собранный фронтенд (`client/dist`), а Socket.IO обслуживает игроков и зрительский экран. Состояние комнат и очки хранятся в памяти процесса. Большой `.siq` загружается во временный файл, распаковывается на диск и медиа отдаётся потоками, поэтому архив не занимает несколько копий в RAM.

## Локальный запуск

В корне проекта:

```bash
docker compose up --build
```

Откройте `http://localhost:5174`. Для телефона в той же Wi‑Fi сети используйте локальный IP компьютера, например `http://192.168.1.10:5174`.

## Production-образ

Dockerfile использует двухэтапную сборку: TypeScript-сервер и Vite-клиент компилируются в build-этапе, а в итоговый образ попадают только production-зависимости, скомпилированный сервер и `client/dist`.

```bash
docker build -t sigame-web .
docker run --rm -p 5174:5174 sigame-web
```

## Переменные окружения

- `PORT` — порт HTTP и Socket.IO. По умолчанию `5174`; Railway передаёт собственное значение автоматически.
- `HOST` — адрес прослушивания. По умолчанию `0.0.0.0`; менять для Railway не нужно.
- `PACK_UPLOAD_LIMIT_MB` — максимальный размер `.siq`, по умолчанию `300` МБ.
- `TMPDIR` — каталог временных файлов. В контейнере по умолчанию используется `/tmp`; для больших паков нужен свободный диск не меньше размера архива плюс распакованное содержимое.
- `SOCKET_IO_ALLOWED_ORIGIN` — необязательный origin для ограничения Socket.IO. Если не задан, соединения разрешены с любого origin.

## Healthcheck

`GET /health` отвечает JSON с HTTP `200`, если сервер запущен. На Railway укажите `/health` в настройках healthcheck. Порт healthcheck должен совпадать с переданным Railway `PORT`.

## После перезапуска

После перезапуска загруженный `.siq` нужно загрузить заново. Для развёртывания на Railway смотрите [RAILWAY.md](RAILWAY.md).
